# 《未完成的星路》製作分工

## 工作原則

所有成果由同一個整合流程完成並提交到 `key8745-netizen/ibisgame`。使用者不需要安裝遊戲引擎、Node、素材包或其他外部工具。

本對話無法直接呼叫 Gemini、Grok、Claude 外部模型，因此採用四個固定工作角色執行其責任，最後由 System Director 整合；不要求使用者在模型之間搬運內容。

## 1. System Director／Integrator

負責：

- 鎖定技術基線與可玩範圍
- 維護敘事 SSOT
- GitHub 分支、PR、版本與回退
- Netlify 靜態部署
- 效能、相容性與最終驗收

## 2. Narrative & Visual Design（Gemini workstream）

負責：

- 把 Beat Sheets 轉成可操作場景
- 超任後期至早期 32-bit 像素視覺規格
- 場景分層、角色輪廓、UI、色盤、光影與特效
- 確保小孩不用先讀完整設定也能理解眼前目標

## 3. Red Team & QA（Grok workstream）

負責：

- 找出卡關、軟鎖、角色切換死路與存檔問題
- 檢查敘事是否被玩法誤解
- 檢查效能、觸控、鍵盤與不同畫面尺寸
- 守住不可逆事件與角色弧線，不用方便玩法破壞故事

## 4. Implementation（Claude workstream）

負責：

- HTML5 Canvas 2D 引擎
- 固定時間步進與 60 FPS 目標
- 碰撞、鏡頭、動畫、粒子、對話、目標與存檔
- 桌面鍵盤與平板觸控
- 零外部套件、零建置步驟的 Netlify 專案

## 第一個可玩段落

採用 C01：

- `同一座標的兩個入口`
- `五年後第一次共同救人`

### 玩家實際操作

1. 操作長子尤哈尼啟動兩處正式橋梁支撐。
2. 切換長女珊妮解除兩處地下／例外道路封鎖。
3. 依受困者需要切換角色完成三次救援。
4. 其中一名孩子需要兄妹都在附近，驗證兩人不能各走各的。
5. 完成後鎖定「重新同行，但尚未和解」的敘事結果。

## 視覺與流暢度基準

- 內部解析度：480×270
- 顯示：整數感等比放大、像素邊緣不模糊
- 更新：固定 60 Hz 邏輯步進
- 畫面：多層背景、捲動鏡頭、水面動畫、角色步行動畫、互動脈衝、粒子與畫面震動
- 風格：超級任天堂後期／早期 32-bit 主機感，不採簡陋方塊原型作為交付品質

## 部署

Netlify 設定：

- Build command：留空
- Publish directory：`.`
- Branch：可先使用 `agent/playable-slice` 預覽，通過後再合併 `main`
